# 浏览器 AI 玩家

房主在桌面或手机的「AI玩家」中添加或移除 AI，并选择昵称、买入次数和牌手风格。添加 AI 时服务端锁住下一局，直到关闭添加面板。每个 AI 使用固定 `playerId`、独立 WebSocket 和浏览器运行锁；刷新页面后以原身份恢复。手机端同样显示管理入口。浏览器关闭期间 AI 不会行动。

## 模型配置

模型由游戏 API 服务端统一配置。Wrangler 本地运行读取 Git 忽略的 `.dev.vars`，字段示例见 `.dev.vars.example`：

- `AI_MODEL`：模型 ID，当前部署使用 `deepseek-v4-flash`。
- `AI_API_URL`：Chat Completions 端点。
- `AI_API_KEY`：仅服务端使用的模型凭据。
- `AI_THINKING`：可选；当前部署设为 `disabled`，减少推理延迟以适配 10 秒行动窗口。

页面没有模型配置、API Key 或代理选项。添加表单会先自动生成一个随机昵称，仍可手动修改。首次进入牌桌时会清理旧浏览器模型资料与旧 AI 玩家记录，并让该桌旧 AI 起身；需要重新添加 AI。新版本添加的 AI 在页面刷新后继续恢复。

## 行动流程

1. AI 用固定身份加入、坐下，并接收自己的牌局 snapshot。
2. 轮到它行动时，浏览器向 `/api/cmd` 发送 `aiAction`，包含桌号、桌密码、玩家 ID、水平和当前回合标识，不发送手牌或模型密钥。
3. Durable Object 核对桌密码、该玩家是否正在行动，以及回合是否一致；同一回合只接收一次 AI 请求。
4. 服务端读取该玩家的真实 snapshot，构造只含可见信息的提示词，调用配置的 Chat Completions 端点。
5. 服务端校验模型动作、按合法下注范围约束金额，再确认回合仍有效并提交动作。模型失败时返回错误，浏览器显示“模型异常”、让 AI 离座并停止本页运行；刷新后可重新尝试。

模型请求限制为 7 秒，浏览器等待服务端结果最多 8.5 秒，游戏行动窗口为 10 秒。两人 All-in 发牌次数默认选一次。下注区保留底池比例快捷键，并提供 2BB、3BB 和直接输入金额；结算默认停留 15 秒，房主可以暂停、继续或立即开始下一局。

## 日志

运行 `docker logs easy-poker-api`，按 `"event":"ai_model"` 过滤。每次模型请求有 `requestId` 和 `start`、`success` 或 `error` 阶段；成功记录耗时、动作、结束原因和 token 数，失败记录错误码、上游 HTTP 状态与耗时。页面错误也包含相同 `requestId`。日志不记录 API Key、提示词、模型回复或手牌。

## 范围

只有创建牌桌的浏览器显示 AI 管理入口，这是现有的界面级房主限制。服务端模型请求还要求桌密码、当前行动身份和唯一回合；整个游戏服务仍面向受邀的朋友间使用。`scripts/agent.mjs` 是独立的命令行 Agent，仍使用它自己的 `.env` 模型配置。
